# 적토행정사사무소 홈페이지 (Jekyll + GitHub Pages)

jukto.net을 Figma Make에서 GitHub Pages로 이전하기 위한 Jekyll 프로젝트입니다.
콘텐츠는 기존 jukto.net(홈/대표인사말/회사소개/전문분야/이력/자료실/문의)과, 준비 중이던
기업 고객 중심 4분류 개편안(Figma Make 초안)을 반영해 만들었습니다.

## 1. GitHub에 올리기 (GitHub Desktop 사용, 코드 지식 불필요)

1. https://desktop.github.com 에서 **GitHub Desktop** 설치 후, 이미 가지고 계신 구글 이메일로
   만든 GitHub 계정으로 로그인합니다.
2. GitHub 웹사이트(github.com)에서 **New repository** 클릭 → 이름을 `jukto-homepage` 등으로
   정하고 생성합니다. (Public으로 시작해도 되고, 소스를 숨기고 싶으면 Private + GitHub Pro
   결제 후 진행)
3. GitHub Desktop에서 **File → Clone repository** 로 방금 만든 저장소를 내 컴퓨터에 받습니다.
4. 클론된 폴더 안에 **이 프로젝트 폴더의 파일 전체**를 복사해 넣습니다.
5. GitHub Desktop 화면 왼쪽에 변경된 파일 목록이 뜨면, 하단에 커밋 메시지(예: "첫 사이트 업로드")를
   적고 **Commit to main** → **Push origin** 클릭.
6. GitHub 저장소 페이지에서 **Settings → Pages** 로 이동 → Source를 `main` 브랜치, `/ (root)`로
   설정 → Save.
7. 몇 분 후 `https://[사용자명].github.io/jukto-homepage/` 로 접속되면 성공.

## 2. jukto.net 도메인 연결

1. 저장소에 `CNAME` 이라는 이름의 파일(확장자 없음)을 만들고 내용에 `jukto.net` 한 줄만 넣습니다.
2. 도메인을 구매한 곳(가비아, 후이즈 등)의 DNS 설정에서 아래를 추가합니다.
   - A 레코드 4개를 GitHub Pages IP로: 185.199.108.153 / .109.153 / .110.153 / .111.153
   - 또는 www용으로는 CNAME 레코드를 `[사용자명].github.io`로
   (정확한 최신 IP는 GitHub Pages 공식 문서에서 재확인 권장 — 확인 필요)
3. Settings → Pages에서 Custom domain에 `jukto.net` 입력 후 저장, HTTPS 적용까지 몇 분~몇 시간
   소요될 수 있습니다.

## 3. 로컬에서 미리보기 (선택사항)

Windows에 Ruby가 설치되어 있다면:

```
bundle install
bundle exec jekyll serve
```

후 `http://localhost:4000` 에서 미리 확인할 수 있습니다. 설치가 번거로우면 이 단계는 건너뛰고
바로 GitHub Pages에 올려서 확인해도 됩니다.

## 4. 글 올리기 (인사이트/블로그) — 네이버 블로그 대신 자체 홈페이지에 직접 작성

`_posts` 폴더 안에 `2026-09-20-제목.md` 형식으로 파일을 추가하면 `/insights/` 페이지에
자동으로 나타납니다. 예시 글이 이미 하나 들어있으니 참고하세요. 네이버 블로그처럼 별도
플랫폼에 옮겨 쓸 필요 없이, 이 저장소 안에서 글을 쓰고 Push만 하면 바로 홈페이지에 게시됩니다.

- `category:` 항목에 전문서비스명(예: `공장·사업장 인허가`)을 적으면 카드에 분야 태그가 붙습니다.
- 최용석 행정사 사무소(choiys7389.co.kr) 블로그처럼 "OO 신청 방법", "OO 비용은 얼마" 같은
  질문형 제목이 검색·AI 인용 모두에 유리합니다.

## 5. 성공사례 (신규)

`_cases` 폴더에 실제 처리 사례를 한 건씩 짧게 올릴 수 있습니다. `/cases/` 목록 페이지에
최신순으로 자동 정렬됩니다. 최용석 행정사 사무소 사례처럼 승인서·확인증 이미지 한 장 +
한두 줄 설명이면 충분합니다. 글이 길 필요 없이, 처리 건수가 쌓일수록 신뢰 자산이 됩니다.
예시 파일(`_cases/0000-예시-공장설립등록-완료.md`)을 참고해 실제 사례로 교체하세요.
고객 상호명 등 특정 가능한 정보는 동의 없이 노출하지 마세요.

## 6. 반드시 검토가 필요한 항목 (확인 필요)

- `privacy.html` (개인정보처리방침): 표준 골격만 작성되어 있습니다. 실제 수집 항목·위탁 현황에
  맞춰 채워 넣고 검토 후 게시하세요.
- `faq.html`: 일부 답변이 `[답변 작성 필요]`로 표시되어 있습니다.
- `resources.html`: 기존 PDF 자료 목록은 옮겨왔지만 실제 파일은 다시 업로드해야 합니다.
- 서비스 페이지의 "근거 법령"은 법령명만 표기했고 조문·최신 개정 여부는 표시하지 않았습니다.
  게시 전 국가법령정보센터(law.go.kr)에서 확인하세요.
- 주소가 기존 사이트에 "화성시 만세구 팔탄면"과 "화성시 팔탄면" 두 가지로 나타나 있었습니다.
  `_config.yml`의 `company.address`에는 프로필상 정확한 표기인 "화성시 팔탄면"으로 넣었으니,
  실제 정확한 행정구역명을 다시 한 번 확인해주세요.

## 파일 구조 요약

- `_config.yml` : 사이트 전역 설정 (회사 정보, 플러그인)
- `_layouts/`, `_includes/` : 공통 레이아웃 (헤더/푸터/서비스 상세/성공사례 템플릿)
- `_services/` : 전문서비스 5개 상세 페이지 (기업 인허가 및 사업장 행정 우선 배치)
- `_cases/` : 성공사례 (실제 처리 건 기록)
- `_posts/` : 인사이트(블로그) 글 — 자체 홈페이지 내 작성
- `assets/css/style.css` : 디자인 (Navy #12233F, Noto Serif/Sans KR, 상단 신뢰 배지 스트립 포함)
- `robots.txt`, `llms.txt`, `sitemap.xml`(자동 생성) : 검색엔진/AI 크롤러 설정

  jukto 사이트의 `_posts`/`/insights/` 구조가 정확히 같은 역할을 합니다.

  방식이 인상적이어서 `_cases`/`/cases/` 로 그대로 옮겼습니다.
- **서비스 구성**: 비영리법인·기업인증·인허가신고·공공조달 4분류로, 김경록 대표님이 하시는 일과

  부동산 연계)**가 확실한 차별점이라, `/expertise/` 페이지에 별도로 강조 문구를 넣었습니다.

  요소로 홈 상단 신뢰 배지, 회사소개 협업 네트워크 섹션에 추가했습니다.
